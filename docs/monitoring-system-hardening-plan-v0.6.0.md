# kt_iot_hub 監視システム強化 実装計画（v0.6.0）

- 作成日: 2026-05-26
- 対象: `docs/monitoring-system-review-2026-05.md` で抽出した改善候補のうち、まずは **監視継続性 / 秘匿情報保護 / 通信負荷制御** を優先して実装するための計画
- 目標バージョン: **v0.6.0**
- 前提: オフライン運用を維持し、**TLS は必須化しない**。ただし、**設定で有効化できるオプション機能**として実装する

> 本書は実装前の計画書であり、仕様の破壊やプロトコル変更は行わない。`docs/refactor-plan.md` の不変条件（Tauri コマンド名 / serde 表現 / proto / TOML キー / ログ grep キー）を維持する。

---

## 0. ねらい

1. 監視システムとして致命的な「無音停止」を減らす。
2. DB / MQTT ブローカーに不要な負荷をかけない。
3. LAN 内でも最低限の秘匿性を確保できるようにする。
4. 既存のオフライン導入障壁を上げない。

## 2. 進め方

### Phase 0: ベースライン固定

- `package.json` / `Cargo.toml` / アプリの表記を **v0.6.0** に揃える。
- 既存の設定ファイルや proto の互換性を壊さないことを再確認する。
- 変更対象を `docs/monitoring-system-review-2026-05.md` と本計画書に限定する。

### Phase 1: 秘匿情報の分離

- `drivers.toml` / `publishers.toml` のパスワードを平文保存しない。
- OS キーリングへ保存し、TOML には参照キーのみ残す。
- 既存の「空文字なら既存値維持」ルールはこのタイミングで共通化する。
- 受け入れ条件:
  - TOML に秘密値が残らない。
  - 既存の設定読み込み・更新フローが壊れない。

### Phase 2: TLS をオプション実装

- MQTT と PostgreSQL の両方に TLS 設定を追加する。
- 既定値は無効のままにして、オフライン運用の導入障壁を維持する。
- 証明書は以下を想定する:
  - サーバ証明書 + CA ファイルの手動配置
  - 自己署名証明書
  - 必要ならクライアント証明書
- 受け入れ条件:
  - TLS 無効時は従来互換。
  - TLS 有効時は接続失敗理由が UI / ログ で判別できる。

### Phase 3: 監視継続性の改善

- ドライバ子プロセスを監視し、終了時に状態へ反映する。
- 必要に応じて指数バックオフ付きで再起動する。
- MQTT event loop の再接続時もバックオフを入れる。
- 受け入れ条件:
  - 子プロセスが落ちたことを本体が検出できる。
  - 短時間に warn が連打されない。

### Phase 4: 通信先への負荷制御

- PostgreSQL に timeout を導入する。
- MQTT モニタの購読範囲と保持件数を設定化する。
- バックプレッシャの仕様を UI と docs で明示する。
- 受け入れ条件:
  - 過負荷時の挙動が予測できる。
  - DB / broker に不要な連続負荷をかけない。

### Phase 5: UI / docs / 検証

- 新しい設定項目の説明を `docs/config-spec.md` に追記する。
- `docs/roadmap.md` に v0.6.0 の完了条件と関連リンクを残す。
- 追加した設定や挙動を UI に反映する。
- `cargo fmt` / `cargo test` / `npm run check` を通す。

## 3. 実装順の詳細

1. **Version bump の準備**
   - v0.6.0 の基準点を作る。
   - 変更履歴の起点が分かるようにする。
2. **秘密情報の分離**
   - 平文保存を先に解消する。
   - TLS 設定追加の前提を整える。
3. **TLS オプション**
   - MQTT → PostgreSQL の順で対応する。
   - どちらも既定無効で安全側に倒す。
4. **死活監視と再起動**
   - ドライバプロセス監視を入れる。
   - 再起動方針は指数バックオフ + 上限回数。
5. **timeout / backoff / monitor 上限**
   - 通信相手に過負荷をかけないための抑制策を追加する。
6. **仕上げ**
   - docs と UI を同期し、手動確認を実施する。

## 7. 補足

- TLS は**使えるようにする**が、ローカル認証局が無い環境でも運用可能な設計にする。
- 将来的に認証が必要になった場合に備え、設定項目は「無効 / CA 指定 / クライアント証明書」の段階拡張ができる形にしておく。
- 細かな観測性改善（M-11 / M-12 / M-13 / M-15 / M-17）は、v0.6.0 の後続改善として切り出してよい。
